# Расширения One в tududi

Форк добавляет минимальные доверенные расширения при сборке. Произвольные пакеты и горячая загрузка не поддерживаются.

## Подключение

- Серверный реестр: `backend/extensions/index.js`. Маршруты регистрируются после общей аутентификации и проверки подписки для обоих префиксов API. Собственные маршруты дополнительно проверяют доступ к исходным объектам.
- MCP: тот же реестр подключается через `backend/modules/mcp/toolRegistry.js` для HTTP и stdio. Проверка прав выполняется в общем сервисе, не только в HTTP middleware.
- Интерфейс: `frontend/extensions/index.tsx` перечисляет id, версию, путь, название и лениво загружаемую страницу. App подключает маршруты, SidebarBoards — пункты меню.
- Новый модуль не должен создавать вторую копию задач. Его собственные данные требуют миграции и проверенного экспорта/импорта. Внутренние модули не изолированы от процесса приложения и базы.

## История и поиск

Страница `/extensions/history` и API `/api/v1/extensions/history/search?query=...`. Параметры `limit` (1–100) и `offset` задают страницы. Запрос — лексический поиск по любому значимому слову, кавычки сохраняют фразу. Нормализуются Unicode, регистр кириллицы и ё/е. Это не семантический поиск и не доказательство отсутствия темы при нулевой выдаче.

Полные тексты задач, заметок и комментариев читаются с текущими правами. Унаследованное название задачи не считается совпадением в тексте комментария. Источники возвращают UID, автора, даты записи, точные строки, найденные таймкоды и ссылки. Дата записи или импорта не выдаётся за дату встречи. Результат содержит `has_more`; агент должен запрашивать следующие страницы при необходимости.

Полный источник и доступные связанные материалы: `/extensions/history/source/:type/:uid`. Поддерживаются `task`, `note`, `comment`. Поиск связей использует отношения задач и явные ссылки на доступные источники. Штатные wiki-ссылки по названиям не переписываются автоматически в UID.

MCP-инструменты: `search_history` и `history_source`. Старый инструмент `search` и штатный глобальный поиск сохраняют свою прежнюю семантику; для полного поиска истории использовать новые инструменты и страницу.

ИИ запускается только по действию пользователя. `/extensions/history/answer` возвращает один JSON-ответ, `/extensions/history/answer/stream` — NDJSON-события `sources`, `delta`, `done` либо `error`. Фрагменты передаются через существующие настройки провайдера пользователя; ключ не передаётся клиенту. Контекст ограничен восемью источниками. Ответ не является исчерпывающим обзором архива; полные источники доступны отдельно. Есть замеры поиска, первого видимого текста и полного ответа. Это ответы на отдельные вопросы, без постоянной истории диалога и без автоматического изменения задач.

Первая версия читает доступный корпус при запросе. Отдельного поискового сервера, векторной БД и фоновой очереди нет. При росте корпуса измерить время/память и только затем вводить индекс. Доступ проверяется при каждом чтении; результаты модели нельзя сохранять в общий для всех пользователей кэш.

## Безопасное редактирование заметок

GET заметки возвращает `revision`. Для изменения `title`, `content` или `tags` передать `expected_revision`; без неё API отвечает 428. При устаревшей версии — 409. Текст, новая версия и теги записываются в одной транзакции. Однократные косметические операции остаются совместимыми с прежними клиентами.

MCP `update_note` требует `expected_revision` из `get_note`. Нельзя автоматически подставлять новую версию и повторять устаревшее содержимое: сначала перечитать, затем объединить изменения.

При конфликте браузер сохраняет черновик отдельно по пользователю и UID заметки; раздел «Черновики конфликтов» позволяет скачать текст или создать отдельную заметку. Это восстановление конфликтной правки в том же браузере, не общая история версий и не серверный backup.

## Резервирование

Штатный формат 2 дополнен `data.history` с версией 1: комментарии и ответы, реакции, отношения задач, события, дневные планы и ссылки на общие проекты. Восстановление выполняется после создания всех аккаунтов экземпляра и использует UID, не исходные числовые ID. В персональном импорте неизвестное исходное авторство комментария сохраняется как метаданные; отсутствующие внешние ссылки учитываются в `missing_references`.

Восстанавливать такой архив следует этой версией форка: оригинальный tududi может проигнорировать дополнительную историю. Старые архивы не содержат отсутствующие данные, и исправленный импорт их не восстанавливает из ничего. Полная холодная копия SQLite, uploads и конфигурации остаётся отдельным способом восстановления.

## Проверки

Целевые интеграционные сценарии находятся в `backend/tests/integration/one-foundation-history.test.js`. Они покрывают конфликт, отсутствие версии, атомарность тегов, кириллицу, права и отзыв доступа, записи сотрудника в проекте владельца, общую выдачу UI/MCP, изоляцию контекста модели, поток ответа, перенос истории и миграцию свежей схемы.

Тесты запускаются на отдельной БД. Для проверки данных действующего экземпляра использовать HTTP API или открывать SQLite строго read-only. Не запускать Sequelize под root против рабочей БД контейнера: создаваемые WAL/SHM могут получить неподходящего владельца.
