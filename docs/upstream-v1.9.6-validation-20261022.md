На ширине 390 px исходный текст и навигация по совпадениям доступны. Поиск контрольной темы вернул 42 результата; серверное время в наблюдавшихся запросах — около 204–236 мс. Это время поиска, не замер полного ответа чата или LLM.

Длинный мобильный ввод: 80 строк, `scrollHeight=4431`, поле высотой 300 px с `overflow-y:auto`. При viewport 390×500 высота поля уменьшилась до 200 px, действия остались видны. Текст не сохранялся. Это проверка уменьшенной доступной высоты, а не испытание экранной клавиатуры физического телефона.

Скриншоты и полные журналы остаются в частной папке проверки; они содержат рабочие материалы и не публикуются.

## Отдельная находка в команде миграций

Вспомогательный `node backend/scripts/db-migrate.js` попытался повторить 168 миграций поверх снимка с 168 записями в `SequelizeMeta` и завершился `Validation error`. На новой одноразовой копии это воспроизведено и до обновления. Рабочая БД не затронута. Этот скрипт не является командой миграций штатного production `start.sh`.

Для этого обновления использовать проверенный штатный путь через `sequelize-cli`, не повторять вспомогательный скрипт на пилоте. Причину расхождения двух механизмов нужно исследовать отдельно; маркировать все миграции применёнными или менять данные ради обхода ошибки нельзя.

## Порядок принятия и откат

1. Сначала обсудить результаты и существующие падения тестов. Этот отчёт не разрешает развёртывание.
2. До изменения пилота согласовать поведение Telegram: v1.9.6 выключает его по умолчанию; включение требует явного `TELEGRAM_ENABLED=true` и отдельного решения о внешних подключениях.
3. Перед будущим развёртыванием остановить обмен безопасно после текущей операции, остановить только Compose-проект `ws-lab-tududi` и сделать свежую согласованную копию SQLite/WAL/uploads/конфигурации. Проверить восстановление.
4. Запускать утверждённый image ID только с правильным Compose project name и проверить данные/API/UI перед возобновлением обмена.
5. При откате остановить новый экземпляр, сохранить его данные для разбора и восстановить старый образ вместе с соответствующей полной копией. Простого понижения бинарников поверх изменённой БД недостаточно.

Рабочий пилот в рамках этой проверки не обновлялся; после всех проверок повторно подтверждены прежний image ID и состояние running. Созданные тестовые контейнеры остановлены, снимки и журналы сохранены. Изменения интерфейса и контракта планирования из #1–#2 не выполнялись. LLM benchmark, внешние вызовы и двусторонний обмен копии не запускались. Физический телефон, полный ручной обход всех экранов и новый цикл обмена с One остаются непроверенными.
